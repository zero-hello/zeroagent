# Workspace test environments

Run host tests with `gradlew.bat :workspace:testDebugUnitTest` on Windows (or `./gradlew` on Unix). `HostShellRunner` uses Android `/system/bin/sh`, Unix `/bin/sh`, or a POSIX `sh` available on Windows `PATH`, such as Git for Windows. The shell fixtures use only POSIX builtins, so a full Unix utility suite is unnecessary. They still verify working-directory writes, exact multiline stdin including a final unterminated line, immediate EOF, output truncation, background process termination, and timeout handling.

Run the POSIX filesystem checks on an Android emulator or device with `gradlew.bat :workspace:connectedDebugAndroidTest`. `RootfsPosixExtractionTest` retains the relative `../../bin/hello` link and executable-file assertions from `ExampleUnitTest`, and the Alpine absolute `/bin/busybox` shell-link and shell-selection assertions from `RootfsInstallerTest`. It additionally checks exact relative link targets, link contents, mode 0755, and rejection of a link escaping the rootfs. These checks run on the actual target filesystem, without requesting Windows developer mode, administrator rights, or symbolic-link privileges.

The JVM still exercises rootfs HTTP downloading, regular-file/directory extraction, Alpine `./` prefixes, shell discovery, unknown tar-entry padding, and both slash/backslash traversal rejection without changing an outside sentinel. A relative symlink escape is rejected before any link creation and is checked on both JVM and Android. No test is skipped based on host capabilities, and production rootfs containment or tool approval rules are unchanged.
