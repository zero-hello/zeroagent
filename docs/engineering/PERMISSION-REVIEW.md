# 權限等級與獨立 Review Agent

此功能接續已合併的 PR #3，從 `main` 的 `65c3be1` 建立獨立 PR。

已提交 [PR #5：美化權限等級並以獨立 Review Agent 代為核准](https://github.com/zero-hello/zeroagent-private/pull/5)，尚未合併或發布正式版本。

## 行為與驗收

- 要求核准：保留人工核准及使用者明確授予的此對話工具授權。
- 代我核准：每次工具呼叫都使用目前模型發出獨立審查請求，獨立 session、乾淨上下文、無工具、無聊天自訂 prompt 或自訂 request body；審查不能執行工具或替其他呼叫授權。
- Review Agent 依原始使用者意圖、近期文字上下文、工具說明及完整參數判斷。僅明確安全且符合任務的操作可放行；有風險、不確定、審查格式錯誤、逾時、缺乏上下文或連線失敗皆轉人工。取消必須中止，不轉成核准。
- 使用者黑名單、Root、MCP 及既有強制逐次確認工具在代我核准模式仍交由人工；命令 hardline、Android 權限與 headless 限制完整保留。
- 完整存取權：保留現有確認風險後跳過一般工具提示的行為，Root 與命令 hardline 仍有效。不可誤導為能繞過 Android 沙箱。
- 真正切換等級時清除舊對話授權，權限 revision 使切回相同等級也無法復用舊審查。每個未執行的 Auto 工具在初次、續跑與執行前皆重查；人工核准只適用原工具呼叫。
- 介面顯示三種圖示、標題、具體說明與單選狀態；完整存取權有風險確認。小螢幕、大字體、RTL 可捲動，點擊區至少 48dp。七語系均提供文案。

## 實作邊界

`ToolReviewAgent` 直接使用既有 provider 的文字生成介面，沒有進入可執行工具的 GenerationLoop，也沒有授予子代理工具。每次使用獨立 session；清除模型內建工具、自訂 request body 與文字工具呼叫解析。只接受具有 `decision` 和 `reason` 兩個字串欄位的完整 JSON；多餘欄位、重複鍵、Markdown、工具輸出及模糊判決都不能核准。20 秒逾時、格式錯誤及 provider 錯誤交回人工，取消則繼續傳遞至原本的停止流程。

`ConversationToolApproval` 統一處理首次提案、人工核准後的同批 Auto 工具、執行前重查。暫時收據只綁定目前對話、呼叫 ID、工具名稱、完整參數與模式 revision；不從訊息 metadata 還原執行權。模式切換及黑名單變動會使舊判決失效。訊息 metadata 僅呈現審查狀態與理由；舊判決失效時更新顯示，不保留誤導的「已核准」。

人工「此對話皆允許」只有在工具仍待核准、名稱一致且模式 revision 未變時才生效。代我核准模式不顯示此選項，也不建立可重用授權；一般核准／拒絕按鈕改為 48dp 並允許換列。

沿用目前模型及供應商，不另傳送到其他服務。審查用量以既有 `SUBAGENT` 類別記帳。沒有新增相依套件、資料庫遷移或備份格式，未變更正式簽章與版本號。

## 測試限制

審查請求隔離、判決解析、逾時、取消及權限失效使用可控制的假供應商驗證，不使用付費 API 金鑰，亦未宣稱對特定真實模型完成安全判斷評測。實際判斷品質與延遲取決於使用者選定的模型；不確定或無法審查時會交回人工。

測試使用獨立 `ZeroAgent_PermissionReview_API35`／`emulator-5558` 與 `app.zeroagent.debug`，不操作其他任務的模擬器、正式套件或使用者資料。真機 Root、系統授權對話的 OEM 差異及實際網路服務仍需對應環境；現有底層限制未調整。
